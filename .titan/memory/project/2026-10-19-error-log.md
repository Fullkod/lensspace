# Error log with WhatsApp alerts (LEN0001)

Date: 2026-10-19

Plan: `.titan/plans/prp-error-log-whatsapp-alerts.md`. Tasknic: LEN0001.

- Unexpected errors land in `private.error_groups/error_occurrences/error_alerts`,
  grouped by fingerprint (source + normalized route + first line with ids/numbers
  normalized). Read only through platform-admin RPCs; panel at `/errors` («Errores»).
- Capture: `src/instrumentation.ts` (`onRequestError`, server), `src/instrumentation-client.ts`
  (window errors), `(main)/error.tsx` and `global-error.tsx` (only without `digest`),
  `friendlyError` (technical errors it masks) and `recordServerError` for handled
  server failures. Only in production builds.
- Server writes use the narrow secret `ERROR_LOG_INGEST_SECRET` (Vault
  `lensspace_error_ingest_secret`), never the service role. Browser writes: signed-in
  users, 20 per 10 min. Text is redacted in the DB; context is whitelisted.
- WhatsApp: one per new group or regression, max 6 per hour, to
  `platform_provider_profile.phone`, via Edge Function `send-platform-alert`
  (`verify_jwt` off, `x-wa-secret`). OpenWA 5xx = `provider_unconfirmed` (QA-61).
- Retention: occurrences and alerts 90 days (cron `lensspace-error-log-cleanup`).
- New handled-error spots: call `recordServerError({ source: 'server_handled', ... })`
  on the server or rely on `friendlyError` in the browser; skip network, permission
  and Spanish business messages.
